lorentz_fit_all_qpoint
~~~~~~~~~~~~~~~~~~~~~~

**Syntax**

.. code-block:: text

   lorentz_fit_all_qpoint = 1

**Meaning**
   Fits the spectral peaks at every generated q-point using
   ``fitting_function = auto | lorentz | dho``. Per-q-point fitting figures are
   written to ``Fitting-Qpoint/``. Per-q-point and combined frequency-lifetime
   data are written to ``Lifetime/``. After all q-points are complete, pySED
   also writes ``Fitting-Frequency-Lifetime.png`` beside the main SED figure,
   with frequency on the horizontal axis and lifetime on a logarithmic
   vertical axis.

   The output layout is:

   .. code-block:: text

      Fitting-Qpoint/
         Fitting-0-qpoint.png
         Fitting-<q-index>-qpoint.png
      Lifetime/
         Fitting-0-qpoint.Fre_lifetime
         Fitting-<q-index>-qpoint.Fre_lifetime
         Fitting-All-Qpoints.Fre_lifetime
      <out_files_name>-SED.png
      Fitting-Frequency-Lifetime.png

   For a partial-SED fit, the lifetime summary figure is placed beside the
   selected partial-SED figure in ``<out_files_name>_partial_SED/``. Numbered
   fitting figures and lifetime tables still use the shared
   ``Fitting-Qpoint/`` and ``Lifetime/`` directories; save an existing
   total-SED fit first if both total and partial results must be retained.

   Fitting does not create separate ``.params``, ``.error``, or ``.models``
   diagnostic files.

Output file contents
--------------------

``Lifetime/Fitting-<q-index>-qpoint.Fre_lifetime`` contains the fitted peaks
for one Q point. It is a whitespace-separated, two-column text file:

.. code-block:: text

   Generated by pySED, Email: liangting.zj@gmail.com
   Frequency (THz)  linewidth-derived SED lifetime (ps); tau_SED = 1/(2*pi*HWHM_THz)
   1.177608 0.41227948
   4.188331 3.66924447

The numerical columns are fitted center frequency in THz and
``tau_SED = 1/(2*pi*HWHM_THz)`` in ps. The file does not contain HWHM,
``Gamma``, fitted amplitude, line-shape model, or a quality flag; those details
are shown in the terminal and fit figure.

``Lifetime/Fitting-All-Qpoints.Fre_lifetime`` concatenates these same two
columns from Q point ``0`` through the last generated Q point. It is intended
for the frequency-lifetime scatter plot and does not include a Q-point-index
column or branch assignment. Use the numbered per-Q files and figures when the
origin or quality of a particular fitted mode must be inspected.

**Default**
   ``0``.

**Notes**
   With ``action = fit``, fitting always runs. With ``action = thinking``,
   fitting runs after the numerical SED data and requested plots exist, but only
   when the requested fit output is still missing.

   The fitting scope in ``thinking`` mode is:

   - ``lorentz_fit_all_qpoint = 1``: if
     ``Lifetime/Fitting-All-Qpoints.Fre_lifetime`` is missing, fit every
     Q point.
   - ``lorentz_fit_all_qpoint = 0`` (the default, including when the parameter
     is omitted): if ``Lifetime/Fitting-<q-index>-qpoint.Fre_lifetime`` is
     missing, fit only the Q point selected by ``qpoint_slice_index``.
   - If the corresponding output already exists, ``thinking`` considers that
     fitting scope complete. It does not compare the old and current fitting
     parameters; use ``action = fit`` to force a refit after changing them.

   Tune the fitting parameters on selected q-points first, then set this
   parameter to ``1`` to fit every q-point.

   All-Q fitting automatically rebuilds the combined lifetime file and redraws
   the frequency-lifetime figure. Therefore,
   ``re_output_total_freq_lifetime`` has no effect when this parameter is
   ``1``; leave it at ``0``. That rebuild switch is intended only for replacing
   one Q-point result with ``lorentz_fit_all_qpoint = 0``.

   If any local fit does not contain both model half-maximum points, the final
   terminal summary lists the affected Q-point and peak numbers under
   ``Q-points to inspect``. Check those figures in ``Fitting-Qpoint/`` before
   using their lifetimes. If peak detection selected an unsuitable local
   basin, refine that Q point by adjusting ``peak_min_significance``.
